Chapter 3 · Talking on the Local Wire

Link Layer

Plug ten computers into the same switch and they all share the same copper, fiber, or air. The link layer is what stops that from being chaos — it gives every device an identity and wraps every signal in an envelope addressed to exactly one recipient.

⏱ 20–25 min read 📋 Prerequisites: Chapter 2 📍 Chapter 3 of 12

From a raw signal to a frame

Chapter 2 got a bitstream from one point to another over copper, fiber, or radio. But a real network isn't two points — it's a room full of laptops, a rack full of servers, a house full of phones, all sharing the same cable or the same air. Something has to answer two questions before any of that raw signal is useful: who sent this, and who is it for?

That's the entire job of the link layer. It chops the continuous stream of bits into discrete chunks called frames, stamps each one with a sender and a recipient, and gives every device on the local network a unique identity to be addressed by. Ethernet does this over wires; Wi-Fi and Bluetooth do a version of the same thing over radio.

Ethernet frames: envelopes for bits

Every Ethernet frame follows the same shape, whether it's carrying a web request or a video call:

FieldSizePurpose
Preamble8 bytesLets the receiver's clock sync up before real data starts
Destination MAC6 bytesWho this frame is for
Source MAC6 bytesWho sent it
EtherType2 bytesWhat kind of payload follows (IPv4, IPv6, ARP…)
Payloadup to 1500 bytesThe actual data — usually an IP packet
FCS4 bytesA checksum so the receiver can detect corruption

That 1500-byte payload ceiling is the Ethernet MTU (maximum transmission unit) — it's why a large file download isn't sent as one giant frame, but as thousands of small ones, each wrapped and addressed independently.

✉️ Analogy: a frame is an envelope

If an IP packet (Chapter 4) is the letter, an Ethernet frame is the envelope it travels in for one leg of the journey. The destination MAC address is the street address written on the front — but it's only valid for the local block. Once the letter reaches a router, it gets taken out of that envelope and re-sealed in a fresh one addressed to the next block over. The letter inside never changes; the envelope gets replaced at every hop.

MAC addresses: burned-in identity

Every network interface — a laptop's Wi-Fi chip, a server's Ethernet port — ships from the factory with a 48-bit MAC address, written as six pairs of hex digits like 3C:5A:B4:12:9F:E1. The first half identifies the manufacturer (an IEEE-assigned block called the OUI); the second half is a serial number the manufacturer assigns. No two network cards are supposed to share one.

There's a broadcast address too: FF:FF:FF:FF:FF:FF. A frame sent to that address is delivered to every device on the local segment — it's how a device asks "does anyone here know who has this IP address?" before it knows anyone's individual MAC address yet. You'll see that exact broadcast in the lab below.

It's worth holding onto one distinction now, because Chapter 4 depends on it: a MAC address is a physical, local identity — like a car's VIN number, fixed for the device's lifetime and meaningless outside the local network. An IP address is a logical, routable identity — like a mailing address, assigned based on where you are, and changeable. The link layer only ever deals in the former.

Switches vs. hubs: who actually gets the frame?

Early Ethernet networks used hubs — dumb repeaters that took whatever came in one port and blasted it out every other port, regardless of who it was addressed to. Every device on a hub had to listen to every conversation and ignore the ones not meant for it, and if two devices transmitted at the same instant, their signals collided and both had to retransmit.

A switch fixes this by actually reading the destination MAC address of every frame and building a table that maps MAC addresses to physical ports, learned automatically from the source address of every frame it sees. Send a frame to a MAC address the switch has already seen, and it's forwarded to exactly one port — not flooded to every device on the network.

📢 Analogy: a hub is a megaphone, a switch is a receptionist

A hub is someone standing in the middle of an office shouting every message to everyone, letting each person figure out if it was meant for them. A switch is a receptionist who's learned everyone's desk — hand her an envelope, and she walks it straight to the right person without bothering anyone else.

🧪 Try it yourself: watch an ARP broadcast happen

Start a Wireshark capture, then from a terminal ping an IP address on your local network that you haven't contacted recently: 

ping -c 1 192.168.1.1

Before the ping itself, look for two ARP frames:

  1. An ARP request, sent to the broadcast address FF:FF:FF:FF:FF:FF, essentially asking "who has 192.168.1.1? Tell me your MAC address."
  2. An ARP reply, sent back directly to your MAC address, from the one device that owns that IP.

Only after that exchange does the actual ping frame go out — addressed, finally, to a real MAC address instead of a broadcast. Run arp -a (or ip neigh on Linux) afterward and you'll see that mapping cached.

Wireless link layer: Wi-Fi and Bluetooth

802.11 (Wi-Fi) frames carry the same core idea — source address, destination address, a payload — but with more bookkeeping, because radio has to manage things a wire never worries about: who's allowed to join, who's transmitting right now, and how to avoid two devices talking over each other on a shared, invisible medium. A Wi-Fi frame's first byte (the Frame Control field) marks it as one of three kinds:

  • Management frames — beacons announcing a network exists, association requests to join it.
  • Control frames — housekeeping like acknowledgments that a frame arrived intact.
  • Data frames — the actual payload, equivalent to an Ethernet frame's contents.

In the common "infrastructure mode," a Wi-Fi access point plays almost exactly the role of a switch — every device associates with it, and it forwards frames between them. Bluetooth (technically IEEE 802.15.1) uses a simpler master/slave model over the same 2.4 GHz band, built for short personal-area links rather than a shared local network.

🧪 Try it yourself: see the frames Ethernet never needs

If your Wi-Fi adapter supports monitor mode, capture raw 802.11 traffic near your own network (capturing traffic you don't own or have permission to observe is off-limits): 

sudo tcpdump -i wlan0mon -e type mgt

You'll see a steady stream of beacon frames — an access point announcing its network name roughly ten times a second, whether or not anyone's listening — plus association and authentication frames whenever a device joins. None of this exists on wired Ethernet, because a cable doesn't need to advertise itself.

⚡ Did you know?

Ethernet frames have a minimum size of 64 bytes, even if the actual data is a single byte — the rest gets padded. That number isn't arbitrary: it comes from the original shared-cable Ethernet standard, where a sender needed to still be transmitting at the exact moment a collision signal could arrive back from the farthest possible device on the network. Any shorter, and a computer could finish sending before it even found out its frame had collided with someone else's. Modern switched networks barely have collisions anymore, but the 64-byte minimum from that 1980s constraint is still part of the Ethernet standard today.

What's next

We can now get a frame to the right device on the local network — but only the local one. MAC addresses don't know how to leave the building, let alone cross the planet. Chapter 4 introduces the layer that does: IP addressing, the ARP process that ties IP addresses back to the MAC addresses we just met, and the routing and BGP that let a packet find its way across the entire Internet.
