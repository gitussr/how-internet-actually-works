Design System

The tokens and components every chapter page is built from. This page isn't part of the reading path — it's the reference that keeps 13 chapters, written one at a time, looking like one site.

🎨 7 color tokens 🧩 6 reusable components 📐 minimal, not exhaustive

Color tokens

Dark, editorial, low-saturation. One accent color (teal) does almost all the work; amber is reserved only for "did you know" facts so it keeps its ability to grab attention.

Typography

Two families only: a serif (Iowan Old Style / Palatino / Georgia) for body copy, because these are long reads, and Segoe UI for anything structural — nav, headings, chips, labels, tables.

Page anatomy

Every chapter — including this one's future siblings — follows the same skeleton:

  1. eyebrow — chapter kicker, e.g. "Chapter 1 · The Physical Stack"
  2. h1.page-title — the chapter title
  3. p.dek — one or two sentences selling why this chapter matters
  4. .meta-row — reading time, prerequisites, chapter number, audience
  5. Sections in the three-pass order: concept → mechanism → lab, each an h2
  6. Callout boxes dropped in where they earn their place (see below)
  7. footer.site-footer — source citations for that chapter
  8. .pager — link back to the previous chapter, forward to the next

Amber accent. Reserved for a genuinely surprising, cited statistic — not general commentary.

Rules of thumb

  • One accent, used sparingly. Teal for structure and interactivity, amber only for facts.
  • Every claim in a fact box is cited in that page's footer — no exceptions.
  • Analogy → mechanism → lab, in that order, per concept — never lab before mechanism.
  • Don't invent new components per chapter. If a chapter seems to need one, it's added here first, then used.
  • Sidebar chapter links flip from locked to live the moment that chapter ships — update every existing page's nav, not just the new one.
